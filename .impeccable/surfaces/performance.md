# Native performance monitoring

Mode: Operate. This brief records the user's approved Sela Performance Canvas, implemented in the existing Rust/egui Windows application for v0.3.0. Both Text only and With background remain explicit choices. Primary success is reading FPS, RAM, VRAM, GPU/CPU utilization and available temperatures, frame time and 1% low on one baseline while closed, without opening a panel. `docs/PERFORMANCE.md` is the product truth source for capture, calculations, export, and compatibility; `src/app.rs`, `src/config.rs`, `src/main.rs`, and `src/performance/` own the native implementation.

Preserve Sela's existing charcoal/sage/amber/ivory, DM Sans, Hack measurements and Pijar world. The gaming line has an 816 × 48 logical-point default and fits the selected monitor width. Text-only mode draws outlined glyphs without a filled panel; background mode keeps the charcoal silhouette. Both remain click-through while closed and never open on hover. Ctrl+Alt+N or the tray provides recovery. Focus completion does not force an expansion over a game. Expanded controls live under System → Performance, with a 600 × 440 panel; System overview is 464 × 440. The native backing window is at most 840 × 440, centered and clipped to its animated drawing/input bounds. Existing media/focus/settings remain.

The controls expose enable/disable, the two radio choices, foreground/visible-application capture, retry, per-executable style saving, frame history, 15/30/60-second benchmark duration/start/finish, latest/previous session comparison, CSV/JSON export and folder opening. The content scrolls within 278 logical points. The graph uses a 58-point raised-charcoal region and the latest 120 presents. Every reading has native widget/AccessKit names or a full compact-line label; all owned copy is English. Windows Narrator remains runtime-unverified.

Real data comes from pinned embedded PresentMon 2.6.0 for presented-frame cadence, sysinfo CPU/RAM, Windows PDH GPU/VRAM fallback counters and optional NVIDIA NVML sensors. CPU/RAM and hardware have system/adapter scope; frames belong to the selected process and dominant swap chain. Missing sensors are unavailable, including CPU temperature. The line uses — and details use Unavailable; production never substitutes demo numbers. Frames expire after two seconds without samples. Recording keeps one process/chain, excludes data gaps, and finishes on target changes or monitoring stop. The explicit `--performance-demo` mode is labelled DEMO and never starts capture. No benchmark session is prefilled; the latest 20 user-created sessions remain until exit.

Capture uses a hidden, hash-verified provider process in a kill-on-close Windows job. Only its private per-user ETW session is stopped/restarted. Monitoring off releases capture/sensors. CPU sampling waits for a baseline; frame history waits for real presents. Foreground mode retains the last target while Sela or the desktop has focus. Capture permission failures explain administrator/Performance Log Users requirements and offer Retry without automatic elevation. GPU/overlay/exclusive fullscreen/anti-cheat behavior requires device testing. The Windows CI probe generates real DXGI presents via WARP to check PresentMon integration; that probe and v0.3.0 installer CI have not yet run.

The implemented line starts with a 66-point Sela/DEMO region, then FPS/RAM/VRAM/GPU/CPU/FT/1% LOW cells of 74/104/110/126/126/92/104 points. DM Sans labels and right-aligned Hack values share a baseline at 24 points; all positions scale with fitted width. Sage marks FPS/1% low, ivory marks ordinary values, and amber marks DEMO, recording, or GPU temperature above 85 °C. Text only outlines the glyphs with no panel; With background uses the existing charcoal shell. These are variants within the incumbent world, not a replacement system.

Native Linux evidence lives in `.qa/native-performance/contact-sheet.png` and individual 100%/150% captures of both line styles, expanded controls and hardware/history. The same capture set covers disabled/unavailable readings, recording, report/export, System overview, Settings, and retained media/focus panels. Published illustrations live in `docs/screenshots/sela-performance-{text,background,panel}.png`. These images establish native layout and states, not Windows game-capture, input-region, hotkey, tray, or anti-cheat execution. No web detector applies to Rust. Windows compilation, ETW integration, installer CI, and device testing must each be reported at their real scope.
